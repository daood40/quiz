# مراجعة الكود

## الترتيب
1. الصحة: هل يفعل ما يُفترض؟ حالات حدية؟ أخطاء غير معالجة؟
2. الأمان: مدخلات غير موثوقة، أسرار، صلاحيات (راجع web-security).
3. الأداء: حلقات مكلفة، N+1، إعادة عرض، تسريب ذاكرة.
4. التصميم: مسؤولية واحدة، تكرار، اقتران، قابلية الاختبار.
5. الوضوح: أسماء، طول الدوال، تعليقات "لماذا".
6. الأسلوب: فقط ما لا يلتقطه linter.

## القواعد
- اقرأ كل التغيير قبل أول ملاحظة.
- كل ملاحظة: الملف:السطر، المشكلة، الإصلاح المقترح بالكود، الأهمية (يجب/يُفضّل/اختياري).
- اذكر ما هو جيد باختصار إن كان مميزًا فعلًا.
- لا أكثر من 10 ملاحظات؛ ادمج المتشابه.
- إن طُلب "أصلح": نفّذ "يجب" فقط، واعرض "يُفضّل" للقرار.

## الخلاصة
- حكم نهائي: جاهز للدمج / يحتاج تعديلات / يحتاج إعادة تصميم، مع السبب في سطر.
