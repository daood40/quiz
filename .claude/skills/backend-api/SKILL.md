# الخلفية و API

## التصميم
- REST واضح: أسماء موارد بصيغة الجمع، أفعال HTTP صحيحة، رموز حالة دقيقة.
- ترقيم بالمؤشر (cursor) للقوائم الكبيرة.
- شكل خطأ موحد: { error: { code, message, details? } }.
- الإصدار في المسار (/v1/) من البداية.

## التحقق والأمان
- كل مدخل يُتحقق منه بمخطط (zod/pydantic) قبل أي منطق.
- لا استعلامات SQL مركّبة نصيًا؛ استخدم ORM أو parameters.
- المصادقة عبر middleware/dependency واحد، لا تكرار.
- الأسرار من متغيرات البيئة فقط، مع ملف .env.example محدّث.
- تحديد معدل (rate limit) على مسارات الدخول والتسجيل.

## قاعدة البيانات
- كل تغيير مخطط = ترحيل (migration) مرقّم، لا تعديل يدوي.
- فهرس لكل عمود يُبحث فيه أو يُربط به.
- معاملات (transactions) لأي عملية تمس أكثر من جدول.
- حذف ناعم (deletedAt) للبيانات المهمة.

## البنية
- طبقات: routes → services → repositories. لا منطق أعمال في المسارات.
- تسجيل (logging) مهيكل بمستويات، بدون بيانات حساسة.

## التسليم
- وثّق كل مسار جديد (OpenAPI أو تعليق واضح).
- اختبار تكامل لكل مسار جديد (نجاح + حالة خطأ واحدة على الأقل).
