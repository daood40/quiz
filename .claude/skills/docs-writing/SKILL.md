# التوثيق

- اعرف القارئ أولًا: مستخدم نهائي، مطور، أم صاحب قرار. اكتب لواحد فقط.
- ابدأ بما يريد فعله القارئ في أول 3 أسطر، لا بتاريخ المشروع.
- README: ما هو، كيف يُشغَّل في 3 أوامر، كيف يُختبر، كيف يُساهَم. ≤ 150 سطرًا.
- أمثلة قابلة للنسخ والتشغيل، مُختبرة فعلًا قبل الإدراج.
- توثيق API: لكل مسار — الطريقة، المسار، المعاملات، مثال طلب واستجابة، الأخطاء.
- ملاحظات الإصدار: جديد / تحسين / إصلاح / كسر توافق، بلغة المستخدم لا بأسماء الملفات.
- العربية: جمل قصيرة، مصطلح إنجليزي بين قوسين عند أول ظهور، ترقيم عربي متسق.
- لا تكرر ما يقوله الكود؛ وثّق "لماذا" و"كيف تستخدم".
- حدّث التوثيق في نفس PR التغيير، لا لاحقًا.
