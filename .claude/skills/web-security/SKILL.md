# المراجعة الأمنية

## قائمة الفحص الإلزامية
1. **الحقن**: أي استعلام أو أمر نظام يُبنى من مدخل مستخدم؟ → استخدم parameters.
2. **XSS**: أي إخراج HTML غير مهرّب؟ → هرّب أو استخدم إطار آمن. أضف CSP.
3. **CSRF**: نماذج/مسارات تغيّر حالة بدون رمز أو SameSite cookie؟
4. **المصادقة**: كلمات مرور مجزأة بـ argon2/bcrypt؟ رموز JWT لها انتهاء؟ refresh يدور؟
5. **التفويض**: كل مسار يتحقق أن المستخدم يملك المورد (لا IDOR)؟
6. **الرفع**: التحقق من النوع والحجم، تخزين خارج جذر الويب، أسماء ملفات مُعاد توليدها.
7. **الأسرار**: لا مفاتيح في الكود أو Git. افحص git log للتسريبات.
8. **الرؤوس**: HSTS, X-Content-Type-Options, X-Frame-Options/frame-ancestors, Referrer-Policy.
9. **CORS**: أصول محددة، لا "*" مع credentials.
10. **الاعتماديات**: شغّل npm audit / pip-audit وأبلغ عن الحرجة.
11. **السجلات**: لا كلمات مرور أو رموز أو بيانات شخصية في السجلات.
12. **الذكاء الاصطناعي**: مدخلات المستخدم إلى LLM معزولة عن التعليمات (prompt injection)، ومخرجات النموذج لا تُنفَّذ مباشرة.

## طريقة التقرير
- رتّب النتائج: حرج / مرتفع / متوسط / منخفض.
- لكل نتيجة: الملف والسطر، المشكلة، الإصلاح المقترح بالكود.
- أصلح الحرج والمرتفع مباشرة إن طُلب، واطلب تأكيدًا لما يغيّر السلوك.
