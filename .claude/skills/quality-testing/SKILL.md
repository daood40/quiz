# الجودة والاختبار

## بعد كل تغيير
1. شغّل الأداة المناسبة: lint + type-check + الاختبارات الموجودة.
2. لا تعتبر المهمة منتهية وفيها اختبار فاشل.

## الاختبارات
- لكل إصلاح خطأ: اختبار يعيد إنتاج الخطأ أولًا ثم يمر بعد الإصلاح.
- لكل ميزة: اختبار المسار السعيد + حالة حدّية + حالة خطأ.
- أسماء الاختبارات تصف السلوك: "يرفض بريدًا غير صالح".
- لا اختبارات تعتمد على الشبكة الحقيقية أو الوقت الحقيقي؛ استخدم mocks وتواريخ ثابتة.

## المراجعة
- اقرأ التغيير كاملًا قبل التعليق.
- ركّز بالترتيب: صحة → أمان → أداء → وضوح → أسلوب.
- اقترح الإصلاح بالكود، لا بالوصف فقط.
- ميّز بين "يجب" و"يُفضّل".

## قبل التسليم
- احذف الكود الميت وconsole.log/print.
- حدّث README أو التوثيق إن تغيّر الاستخدام.
- لخّص: ما تغيّر، كيف اختُبر، ما المخاطر المتبقية.
