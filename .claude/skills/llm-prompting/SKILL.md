# الأوامر والتقييم

## البنية
- system prompt: الدور، المهمة، القيود، صيغة الإخراج، أمثلة 1–3. بهذا الترتيب.
- ضع البيانات المتغيرة في وسوم واضحة (<document>، <user_input>) وافصلها عن التعليمات.
- اطلب صيغة إخراج صارمة (JSON بمخطط) عندما يستهلكه كود.
- للمهام المركبة: اطلب التفكير خطوة بخطوة داخل وسم ثم الجواب النهائي في وسم آخر.
- العربية: حدّد المستوى (فصحى مبسطة) وقواعد الترقيم والأرقام صراحة.

## التقييم
- ابنِ مجموعة ≥ 20 حالة (مدخل + إجابة مرجعية أو معايير) قبل أي تحسين.
- شغّلها بعد كل تعديل وسجّل النسبة. لا تعديل بلا قياس.
- استخدم نموذجًا كحكم بمعايير واضحة للمهام المفتوحة.

## التكلفة
- أصغر نموذج يحقق النسبة المستهدفة. Haiku للتصنيف والاستخراج، الأكبر للتوليد المركب.
- Prompt caching للأجزاء الثابتة الطويلة، وBatch API لغير الفوري.
- قصّ السياق: أرسل المقاطع المطلوبة لا المستند كله.
- max_tokens واقعي، وتوقف مبكر بـ stop sequences.

## الرد
- الأمر النهائي في ملف prompts/<name>.md مع إصدار وتاريخ ونتيجة التقييم.
