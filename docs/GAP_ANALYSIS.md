## 2) موجود يُعدَّل 🔶

| بند التوجيه | الوضع الحالي | التعديل المطلوب |
|---|---|---|
| §16 معادلة النقاط | base حسب الصعوبة + speed bonus بسقف نسبة من settings؛ خطأ/مهلة/تخطٍّ = 0 ✅ | إضافة `streak_bonus` داخل الجولة (min(streak,5)×2)، سقف يومي للنقاط التنافسية، معامل Medium للأسئلة الجديدة (< 200 إجابة)، ومطابقة قيم base الافتراضية (10/20/30/50) في seed الإعدادات |
| §9 منع التكرار للمستخدم | تفضيل غير المُجاب من آخر 500 إجابة | ترقيته إلى `user_question_history` بمنع صريح 90 يومًا في الوضع التنافسي (مع fallback موثق عند نفاد البنك) |
| §15 Grace للشبكة | المهلة خادمية صارمة | إضافة grace ‏1.5s قابلة للضبط من settings عند احتساب `deadline_at` |
| §16 تدقيق الاحتساب | أحداث نقاط بسبب (correct_answer/completion/…) موجودة | توحيدها بصيغة `score_events` الكاملة (مصدر + معامل + مجموع) للإرجاع والتدقيق |
| §13 إصدارات وطعون | مراجعة وبلاغات موجودة | إضافة `question_versions` (المعتمد المعدَّل يعود in_review) و**إرجاع النقاط** لمن تضرر من سؤال ثبت خطؤه خلال الموسم |
| §11 الترجمات | لغة لكل سؤال (`questions.language`) | جدول `question_translations` معتمد + قاعدة اختيار المجموعات العالمية من المترجَم المعتمد |
| §18 Speed / Knowledge | الأوقات والصعوبات قابلة للضبط لكل تحدٍّ | تعريفهما كنمطين جاهزين بإعدادات التوجيه (10ث/معامل سرعة؛ Hard+ بلا مكافأة سرعة) |
| §21 Redis للترتيب | Postgres + snapshots بكاش TTL (يفي وظيفيًا) | إدخال Redis عند عتبة الحمل الموثقة في ADR-002 |
| §25 كشف الأجهزة والتوقيع | كشف سرعة/تكرار/Replay موجود | إضافة `devices` (تعدد حسابات من جهاز)، توقيع الطلبات، وAttestation ‏(Play Integrity / App Attest) مع عميل الجوال |
| §28 الإشعارات | داخل التطبيق كاملة + تفضيلات | إضافة Push ‏(FCM/APNs) وحد يومي لكل نوع |
| §34 التحليلات | دقة/صعوبة/وقت/شعبية/DAU-MAU موجودة | إضافة Retention ‏D1/D7/D30، Funnel، وDrop-off بحسب السؤال |
| §35 الاشتراكات | خطط وحدود جاهزة بلا مزود دفع | ربط مزود دفع خلف الواجهة المجردة + Webhooks |
| §31 فروق المخطط | التسمية/التقسيم يختلفان جزئيًا | عند أول هجرة قادمة: `question_answer_keys` (ADR-004)، `privacy_settings`، `follows`، `devices`، وPartitioning لجدول الإجابات عند النمو |
| الملحق د عقد submit_answer | مطبق ما عدا التوقيع | إضافة `signature valid` مع منظومة توقيع الطلبات أعلاه |

## 3) جديد 🆕

بترتيب الأولوية المقترح (يوافق مراحل §41):

1. **§10 قاعدة تصنيف الدين:** `source_id` إلزامي + مراجع متخصص + منع اعتماد
   مسودة AI دينية بلا مصدر (Validation + صلاحية مراجعة مخصصة). *(المرحلة 1)*
2. **§20 إعدادات الخصوصية:** من يراني/يتحداني، إظهار الدولة والإحصاءات
   (عام/أصدقاء/لا أحد) + Follow أحادي الاتجاه. *(المرحلة 3)*
3. **§12 التكرار الدلالي:** `pgvector` + `question_embeddings` بعتبات
   0.92/0.85 (ADR-007؛ يتطلب مزود Embeddings). *(المرحلة 1–4)*
4. **§14 مولّد AI للمسودات:** يدخل مسار §13 حصرًا، تكلفة وطلبات في
   `ai_requests`، مفاتيح على الخادم. *(المرحلة 5 — الإدارة قد تسبقها)*
5. **§18 عدالة الموسم:** حد جولات تنافسية يومي موحد (مثلًا 3) معلَن في
   الواجهة. *(المرحلة 3)*
6. **§33 قياس الأداء:** Load Testing ‏(10k جلسة متزامنة) وقياس أهداف
   300/150/100ms قبل الإطلاق العام. *(المرحلة 4)*
7. **§39 تشغيل:** Monitoring/Crash Reporting/Runbook لإغلاق الموسم
   والطوارئ. *(المرحلة 4)*
8. **§4 عملاء الجوال:** Flutter على `/api/v1` القائمة (ADR-003). *(مرحلة الجوال)*
9. **§5 الكلمات المتقاطعة** كنمط لعب فوق Fill-in-the-Blank. *(المرحلة 4)*
10. **§5 Realtime 1v1.** *(المرحلة 5)*
