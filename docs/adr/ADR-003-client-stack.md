# ADR-003 — واجهة العميل: React SPA الآن، Flutter لاحقًا

**الحالة:** معتمد بصيغة معدَّلة عن التوجيه v2 (§29 ADR-003).

## السياق
التوجيه يقترح Flutter + Clean Architecture + Riverpod لتوحيد المنصات.
الكود القائم واجهة React (Vite) كاملة الميزات، عربي/إنجليزي RTL/LTR،
فاتح/داكن، مبنية على مبدأ "لا منطق أعمال في العميل".

## القرار
- **الويب:** React SPA القائمة تبقى — إعادة كتابتها في Flutter Web تخالف
  قاعدة أصغر تعديل ولا تضيف قيمة وظيفية.
- **الجوال (Android/iOS):** عميل Flutter يُبنى في مرحلة الجوال على واجهة
  `/api/v1` القائمة كما هي — لا شيء في الخادم خاص بالويب، والعقود REST
  موثقة في `docs/API.md`.
- التزام بنيوي يسري على أي عميل: العرض والإدخال والترجمة فقط؛
  كل النتائج من الخادم (ADR-001).

## البديل المرفوض والسبب
Flutter للويب الآن: بيئة البناء الحالية لا تنفّذ Flutter ولا تتحقق منه،
وإعادة الكتابة توقف التقدم على فجوات أهم (انظر docs/GAP_ANALYSIS.md).
