# ADR-004 — عزل مفتاح الإجابة

**الحالة:** معتمد بصيغة معدَّلة عن التوجيه v2 (§7، §29 ADR-004) — الهدف محقق،
وفصل الجدول تحصين مخطط.

## السياق
التوجيه: `answer_key` في جدول منفصل بصلاحية `service_role` فقط، لأن البديل
(عمود في `questions`) قد يتسرب بخطأ RLS في نموذج Supabase حيث يستعلم
العميل من القاعدة مباشرة.

## القرار
- في البنية القائمة **لا يصل أي عميل إلى القاعدة إطلاقًا** — كل القراءة عبر
  API؛ طبقة `present()` في محرك الأسئلة تعقّم كل سؤال قبل الإرسال (تحذف
  المفتاح وتخلط الخيارات)، وقناة `correct_answer` لا تُقرأ إلا داخل دالة
  التصحيح الخادمية. خطرُ "خطأ RLS" الذي بُني عليه القرار الأصلي غير قائم هنا.
- **التحصين المخطط (Defense in Depth):** نقل `correct_answer` إلى جدول
  `question_answer_keys` منفصل يبقى بندًا معتمدًا يُنفَّذ مع أول هجرة قادمة
  تمس جدول الأسئلة، أو فورًا قبل فتح أي وصول SQL خارجي (Read Replica
  للتحليلات، BI، إلخ) — أيهما أسبق.

## قاعدة ثابتة (من §40)
إرسال مفتاح الإجابة للعميل قبل التصحيح ممنوع في كل الأحوال؛ أي مسار API
جديد يمر عبر `present()` أو يُرفض في المراجعة.
